# Roadmap and current state

Snapshot updated on 2026-11-18. Build, seam-check, and dedicated-server facts are recorded separately from code presence and manual in-game verification in `verification.md`.

## Current foundation

- Target: Minecraft 26.3 / NeoForge 26.3, as an add-on for Thaumcraft 4: Reforged.
- Compatibility interfaces and the `TcReforgedPort` ServiceLoader adapter isolate TC4R APIs; version-specific seams live in `platform/` and `client/platform/`.
- The 74-entry research tree, aspects, English/Russian localization, player infusion attachment, Chameleon Skin redesign, Spider Climb and Warp Tumor are present.
- The main content pass includes 20 creature types, their AI and infusion recipes; golems, lenses, foci; machines; souls, blood and Vat systems.
- Nine menu types are registered: Case, Vat, Soul Sieve, Inspiratron, Soulforge, Blood Infuser, Injector, Fingers and Vis Dynamo.
- Entity renderers are registered for the 20 creature types plus AlchemitePrimed and the TH golem. Node Monitor has a dedicated block-entity renderer. Familiar has a dedicated cutout hat layer built from the original `ModelFamiliar` geometry. The Vat now has a block-entity renderer for the original five-part 3×3 shell (base, water, glass, top and hatch) using the shipped 512×512 atlas, plus a client-only NBT-backed preview for a contained non-player creature. Its blocks use invisible vanilla render shapes to avoid duplicate cubes. The infusion matrix renderer also draws eight rotating/wobbling cubes, an emissive pulse and the additive mode-2 halo. Explicit blockstate selectors cover Vat variants 10–11 and VatSolid variants 4–7. The old mode-1 dissolve fade, effigy/sample previews and all live-client appearance checks remain open.
- The TC4R FX adapter `TcFx` delegates to the fork's `FxProxy`, but individual legacy effects still need parity and runtime checks.

## Pocket Plane — dimension loads, gameplay verification pending

Commit [`e38d16a`](https://github.com/MxxFoxx2/ThaumicHorizonsReforged/commit/e38d16ae8e68544a3dc6d45627b00cc1cf19ce47) moved substantial Pocket Plane work into tracked source files:

- World data and generation: `PocketPlanes`, `PocketPlaneData`, `PocketPlaneGenerator`, `PocketPlaneChunkGenerator`, `PocketNoise` and `PocketDimension`.
- Blocks and portal support: `GatewayPortalBlock`, `PortalTHBlock`, `SlotBlock` and `SlotBlockEntity`.
- Registration and item: `PocketRegistry`, `KeystoneItem`, `PlanarConduitItem`; the `Teleport` TC4R seam is added to the allowlist.
- Data resources: dimension, dimension type and biome JSONs for `pocket_plane`.

This is **not a playable/verified dimension yet**. The Pocket Plane sources compile against Minecraft 26.3 / NeoForge 26.3: the ChunkGenerator contract, SavedData codec, block-removal hook, entity-inside hook, item tooltip API, registry lookup APIs, and block-entity ticker were migrated. Plane generation now resets its per-plane creature budget and draws procedural randomness from the Pocket Plane dimension's world RNG, matching the legacy generator's per-plane reset and world.rand source. The duplicate `thaumichorizons:planarconduit` registration was consolidated into `PocketRegistry`. The dimension type and biome definitions were migrated to the current codecs in `7eb9b8c`; a fresh dedicated-server run reached `Done` and loaded `thaumichorizons:pocket_plane`.

The 2026-11-18 source audit compared the port with the 1.7.10 reference. Its chunk provider also creates empty chunks; the actual sphere/terrain is drawn as a single plane-generation pass, so the modern empty `ChunkGenerator` is intentional. The reference `drawRavines`, `drawClouds`, `drawSurfaceFeatures`, `drawUndergroundFeatures`, and `drawLeviathanBones` methods are empty too, and are not omitted ports. SavedData loading now repairs the next plane ID from the dense saved-plane list and skips malformed/orphaned return-position entries instead of accepting a mismatched counter or substituting `(0,0,0)` ([`73d329a`](https://github.com/MxxFoxx2/ThaumicHorizonsReforged/commit/73d329a3adf79f4e9db0f780b8ea49370ff6f3b3)). This is a static/source result; it does not establish runtime generation or restart correctness.

PR #4 adds another defensive pass to the same subsystem: the source Vortex takes the canonical dense ID from `planes.size()`, persisted plane radii are clamped to the generator's valid 32–127 range, and portal endpoints with incomplete coordinates, invalid dimensions/orientation or the legacy zero-coordinate sentinel are treated as unused and rejected on exit. Keystone client prediction/tooltip no longer reads server-only `PocketPlanes` SavedData, and Gateway teardown closes the saved endpoint before restoring the frame to prevent reentrant removal callbacks. The PR head passes seam-check, Gradle build and JAR validation; frame-break, multiplayer and live travel checks remain manual.

Still pending: live verification of generated terrain layers/caves/pockets, slot geometry and vis cost, Keystone round-trip, all four portal directions, return dimension/position/orientation, portal teardown, SavedData restart behavior, and client assets/rendering for the new blocks. The portal/slot and Keystone paths now exist in source but have not yet been exercised in a live client/server world. The historical `.deferred-pocket/` staging directory is no longer part of the public source state; the current public WIP is in `src/main/java` and `src/main/resources`.

- **Synthetic Node Wisp Essence interaction**: right-click insertion now adds four units per essence of its first stored aspect to the node's maximum capacity; breaking/removing the node returns essence stacks from the maximum aspect capacity with the legacy two-aspect item data. Aspect component access stays behind `ItemCompat`. Code and CI coverage only; the item insertion/drop loop still needs an in-game check.
- **Transduction Amplifier overload**: restored the original 2+/3+/4-amplifier thresholds for magic zaps/damage, randomized Flux Gas/Goo spills, and one-time Vortex conversion. The conversion preserves the energized node's aspect base and stops the overlying TC4R Node Transducer through a newly pinned `stopForVortexConversion()` compatibility API; first-tick redstone state is also initialized. This is code + CI coverage only; runtime behavior still needs the manual checks in `verification.md`. The legacy amplifier implementation does not directly spawn Wisps.
